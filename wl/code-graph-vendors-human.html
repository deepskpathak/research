Code Graph Vendors Compared

Research date: 18 Nov 2026. This note compares industry and open-source code graph tools for four jobs: feeding AI coding agents, running toil reduction campaigns, automated code review, and building knowledge graphs.

Every fact links to a numbered source. Anything marked My read is my opinion, not something a source says. "Vendor-reported" means the vendor did the measuring, and independent benchmarks are rare in this space. I pulled GitHub stars and forks from the GitHub REST API at 02:06 UTC on 18 Nov 2026, and each figure links to its repo. I read "generative agents" as AI coding agents that write code, such as Claude Code, Codex and Cursor.

1. Summary

My read: no single vendor handles all four jobs well. What fits the evidence is a stack. A precise, persistent code graph sits at the bottom. An SDLC graph adds merge request and pipeline context. A deterministic transformation engine runs the campaigns. Agents reach all of it over MCP.

What changed in 2026

Code graphs became agent infrastructure this year. Sourcegraph 7.0 (Feb 2026) recast the product as a shared intelligence layer for developers and AI agents [1]. GitLab Orbit went GA on 29 Oct 2026 [2]. Moderne now calls itself "the Agent Tools company" [3].

MCP is how they all reach agents. Orbit exposes query_graph and get_graph_schema [4]. Sourcegraph serves search, navigation and Deep Search over MCP [5], and Moderne ships its LST engine and Moddy agent the same way [6].

Open-source local graphs took off fast. CodeGraph, created in Jan 2026, has 77,889 stars [7]. codebase-memory-mcp, created in Feb 2026, has 48,789 [8].

SCIP became a shared standard too. It moved to open governance in March 2026, and engineers from Meta and Uber sit on its steering committee [9].

What the evidence says

Graphs help when the answer is several hops away. In KGCompass, 89.7% of the bugs it localized had no location hint in the issue, and the tool found them only by traversing the graph [10].

The catch is that agents often don't call the graph. In CodeCompass, 58% of trials with graph access skipped the tool despite explicit instructions [11]. Graph grounding also costs more per call. In Compare the Market's test, the Orbit-grounded reviewer cost $2.37 per merge request, against $0.58 for diff-only review [12].

2. Terms used here

  • Code graph. Nodes for files and symbols, edges for calls, imports and definitions. Orbit's graph, for example, holds files, directories, definitions, imports and calls [13].
  • SCIP. A language-agnostic protocol for indexing source code. It's what powers go-to-definition and find-references [14].
  • Code property graph (CPG). A graph for mining large codebases for programming patterns, queried with a Scala-based DSL [15]. It merges a syntax tree, a control-flow graph and a program-dependence graph into one structure [16].
  • Lossless Semantic Tree (LST). OpenRewrite's code tree. It keeps whitespace, so it can print the original source back out without reformatting [17], and it carries type information [18].
  • Context graph (or SDLC graph). A code graph joined to lifecycle data. Orbit maps code, work items, pipelines, deployments and production signals into one graph [19]. Graphiti goes further and records when each fact became true and when it was superseded [20].
  • MCP. The Model Context Protocol. Every tool on the shortlist uses it to serve agents [4, 6, 7, 21].

3.4 How teams wire these tools in

I saw six patterns, and most tools support more than one.

  1. A local MCP server beside the agent. CodeGraph, codebase-memory-mcp and Orbit Local all run on the developer's machine [7, 8, 23].
  2. A shared remote endpoint over an org-wide index. Sourcegraph serves /.api/mcp from its instance [21], and Orbit Remote spans a top-level GitLab.com group [23].
  3. Indexing in CI. Sourcegraph recommends running SCIP indexing in CI for complex builds [62]. Compare the Market ran Orbit as a sidecar that re-indexed on every MR pipeline [12].
  4. A review bot with its own graph. Greptile builds a graph when you sign up and queries it on every review [63].
  5. A campaign engine. Sourcegraph Batch Changes opens and tracks PRs across many repos [64], and Moderne runs recipes across thousands of them [65].
  6. Hooks and skills that push context. GitNexus registers Claude Code hooks and writes AGENTS.md and CLAUDE.md files [45]. codebase-memory-mcp installs skills, agent profiles and hooks [8].

4. The shortlist, tool by tool

I picked four industry vendors and four open-source tools, based on how well they fit the four jobs and on traction.

4.1 Sourcegraph

Sourcegraph is a code search and navigation platform, and version 7.0 repositioned it as a shared intelligence layer for developers and agents [1]. It indexes every repository, branch, tag and revision across GitHub, GitLab, Bitbucket, Gerrit, Perforce and Azure DevOps [5]. On top of that index you get structural, semantic and regex search, plus commit, diff and blame history [5]. Go-to-definition and find-references work across repos out of the box [5].

Two features matter most for agents. Deep Search runs agentic, natural-language exploration over the same index [5], and 7.0 made it more accurate, added image support and built code navigation into it [1]. Batch Changes opens a PR on every affected repo and tracks each one until it merges [64]. The agentic version generates reviewable AI changes across thousands of repos [5].

How it works. Precise navigation comes from per-language SCIP indexes that you upload to the instance [62]. Without one, Sourcegraph falls back to search-based navigation [66]. SCIP is optional, and Sourcegraph says search, navigation, Deep Search and MCP all work without it [5].

How teams use it. Agents connect to /.api/mcp, and /.api/mcp/all and /.api/mcp/deepsearch offer other tool sets [21]. Auth is OAuth 2.0 (Dynamic Client Registration included) or access tokens [21]. Campaigns are YAML batch specs that name the target repos, the commands to run and the changeset templates [64].

Cost and deployment. Enterprise Dedicated Cloud is the default, and Enterprise Self Hosted is available on request. Both list at $59 per user per month [22]. Self-hosting runs on Kubernetes with Helm, which Sourcegraph recommends, or on Docker Compose [67].

Watch out for. The MCP server needs an Enterprise plan [21]. Precise data needs a working indexer for each language, and for authenticated builds Sourcegraph recommends indexing in CI [62]. My read: the pages I checked cover code and version history, not pipelines, deployments or vulnerabilities, so SDLC context would have to come from somewhere else.

4.2 GitLab Orbit

Orbit used to be called the GitLab Knowledge Graph. It's a Rust service that builds a property graph from SDLC metadata and code, and you query it with a JSON, Cypher-like DSL that compiles to ClickHouse SQL [68]. It went GA on 29 Oct 2026 [2].

The graph covers default-branch code (files, directories, definitions, imports and calls) plus merge requests, pipelines, vulnerabilities and branches [13]. Code indexing supports Ruby, Java, Kotlin, Python, TypeScript, JavaScript, Rust, Go, C#, C, C++, PHP, Bash and Elixir [23]. The hosted DSL handles aggregations, traversals, neighbors and pathfinding [23]. File content is fetched at query time, so an agent can read code without a second API call [69].

How it works. Orbit comes in two shapes. Orbit Remote runs gkg-server on ClickHouse, fed by change data capture through GitLab's Data Insights Platform [23]. Orbit Local is a single-binary orbit CLI on DuckDB with a stdio MCP server [23].

How teams use it. Agents connect over MCP or with glab orbit setup, and GitLab names Claude Code, Codex, Cursor, OpenCode, Gemini CLI and Antigravity as clients [2]. It's also native in Duo Agent Platform, custom agents can use REST, and engineers get a Data Explorer [2]. The REST endpoints are /api/v4/orbit/query, /schema, /status and /tools [70].

Cost and availability. You need Premium or Ultimate. GitLab.com gets it first, and Self-Managed and Dedicated follow in the coming weeks [2]. Pricing is by query pack: $30 in GitLab Credits per user per month adds 1,000 queries to a pool the whole org shares, and overage runs about $0.03 per query [2]. Schema lookups through get_graph_schema are free, while queries use credits [71].

What GitLab claims. These are vendor numbers. GitLab says it indexed more than 1.5 million projects and 8 TB of graph data in under 2 hours [2]. It also claims up to 11x faster responses with 4.5x fewer tokens [19], and up to 45x fewer retries [2].

Watch out for. Only the default branch gets indexed [13]. The license is GitLab's Enterprise Edition license, not an open-source one [23]. Some MCP clients cut off the long query_graph description, so the model never sees the DSL grammar [72]. And in Compare the Market's pre-GA test, latency was 80.6 s against about 44 s for diff-only review [12].

4.3 Moderne and OpenRewrite

OpenRewrite is an open-source project for semantic analysis and refactoring [52]. Moderne builds on it so you can run its recipes against thousands of repositories at once [65]. The recipes search and transform code held as LSTs [25].

Moderne has layered agent features on top:

  • Moddy, a multi-repo AI agent in restricted beta that runs across thousands of repositories [73].
  • Prethink, launched 10 Feb 2026 [74]. It gives agents pre-resolved context on service endpoints, database connections, external calls, messaging patterns and test coverage [75]. It can also emit an optional knowledge graph and FINOS CALM architecture diagrams [76].
  • Changelog (May 2026), which shows what's ready, blocked or waiting across a changeset through MCP and GraphQL [3].
  • Trigrep, symbol-aware code search for agents [3].

How it works. Run locally, the LST has to fit in memory [17]. Moderne instead serializes LSTs as a build byproduct and edits them in bulk later [65]. Python support arrived in Feb 2026 [77].

How teams use it. Moderne ships the LST engine, recipe catalog, CLI, IDE plugins and Moddy, and serves them to coding agents over MCP [6]. Its pitch is that the agent plans and Moderne's deterministic tools execute [6]. Moddy Desktop runs an MCP server at localhost:4848/mcp [78].

Traction. Moderne raised a $30M Series B in Feb 2025, with Morgan Stanley, Amex Ventures and TIAA Ventures taking part [79]. OpenRewrite is built into Amazon Q and Broadcom App Advisor [79].

Watch out for. Moddy is still in restricted beta [73]. My read: Moderne is strongest on JVM ecosystems, so check recipe coverage for every language and framework you plan to migrate.

4.4 GitHub CodeQL

CodeQL is GitHub's semantic analysis engine. It lets you query a codebase as though it were data [29].

Most teams meet it through GitHub features rather than directly. Copilot Autofix suggests fixes for CodeQL alerts. It's on by default for repos that use CodeQL and doesn't need a Copilot subscription [80], and it runs on pull requests and on the default branch [81]. Copilot code review now mixes LLM detection and tool calling with CodeQL and ESLint [82]. CodeQL is on by default there, while ESLint and PMD start switched off [30]. If you need more framework coverage, you can extend the data-flow libraries with your own sources and sinks [83].

Languages. CodeQL supports C/C++, C#, Go, Java/Kotlin, JavaScript/TypeScript and more, but not PHP or Scala [84]. The standard queries are open source in github/codeql [32].

How teams use it. Default setup picks the languages, query suite and trigger events for you [84]. Code scanning runs on public repos, and on org repos with GitHub Code Security turned on [85].

Watch out for. Without GitHub Advanced Security, you can only use the CodeQL CLI on open-source codebases [31]. My read: CodeQL is a deep analysis database, not a general code graph that agents query over MCP. It suits review and security better than agent navigation, especially for code hosted on GitLab.

4.5 CodeGraph

CodeGraph pre-builds a graph of every symbol, call edge and dependency, so an agent can get the code it needs in one call [7]. A Rust kernel parses 20 languages into a local SQLite database with FTS5, and no data leaves the machine [7]. By default it exposes one MCP tool, codegraph_explore. The narrower tools still work but stay unlisted [7]. It watches the project and updates the graph on every file change [7].

Its own benchmark (7 repos, Claude Opus 4.8) reports 88% fewer tool calls, 53% faster answers, 62% fewer tokens and 44% lower cost [7]. To their credit, the authors also flag a cost: in multi-turn sessions, about 80% more retrieval context stays resident in the window [7]. A hosted PR product has been announced [7].

4.6 codebase-memory-mcp

This tool builds a persistent local knowledge graph that links code to documentation, configuration and infrastructure [8]. The backend is native C, with 17 MCP tools, vendored grammars and hybrid LSP type resolution [8]. The accompanying preprint stores the graph in SQLite and uses Louvain community detection [86]. It reaches past source files into Docker, Kubernetes, Helm, Terraform, Ansible and CI configuration [8].

It's fast. A full index of the Linux kernel (28M lines) takes 3 minutes on an Apple M3 Pro and produces 4.81M nodes and 7.72M edges [8]. Across 31 repos, the authors report 10x lower token use and 2.1x fewer tool calls than file-by-file exploration [8]. The project also publishes OpenSSF Scorecard and SLSA 3 badges [8].

4.7 GitNexus

GitNexus builds a graph of symbols, calls, dependencies and execution flows that you can use through MCP, a CLI or a web explorer [45]. Its tools are query, context, impact, trace, detect_changes and rename [45]. It has 18 language providers, COBOL among them [45]. Parsing uses tree-sitter, and storage is LadybugDB, an embedded graph database with vector support [45]. One shared HTTP MCP server can serve several agents at once [45].

Watch out for. The license is PolyForm Noncommercial. Commercial use, PR blast-radius review and a unified multi-repo graph all sit in the paid enterprise offering [45].

4.8 Joern

Joern turns source code, bytecode and binaries into code property graphs, aimed at vulnerability discovery and static analysis research [53]. The graphs live in a custom graph database, and you mine them with a Scala DSL [53]. Version 4.0.0 moved storage from overflowdb to flatgraph [53]. The CPG idea started with vulnerability hunting in C system code and the Linux kernel [15].

Harness bought Qwiet AI (formerly ShiftLeft) in Sep 2025, and Fabian Yamaguchi, who created the CPG, now works at Harness [43]. Expect a learning curve. Harness's own docs call it steep [87].

6. Use cases

6.1 Generative agents (AI coding agents)

Coding agents rebuild context from scratch on every task, with grep, glob and file reads [5]. A code graph gives them a shortcut.

  1. Answer codebase questions in fewer calls. CodeGraph cut tool calls by 88% in its own benchmark [7], and codebase-memory-mcp reports 10x lower token use [8]. Good fits: CodeGraph, codebase-memory-mcp and Sourcegraph MCP.
  2. Find and fix the bug. RepoGraph improved all four SWE-bench systems it was plugged into (ICLR 2025) [90]. KGCompass reached 58.3% on SWE-bench Lite at about $0.2 per repair [10].
  3. Spot hidden dependencies before editing. CodeCompass scored 99.4% on hidden-dependency tasks, where a vanilla agent scored 76.2% [91].
  4. Ask instead of inventing. One hackathon team's agent checks Orbit, and when it can't find a service, it asks where the real code lives [24].
  5. Edit in dependency order. The hackathon runner-up maps every affected file and edits them in dependency order [24].
  6. Start from architecture facts. Moderne Prethink hands agents verified service endpoints and dependencies, so they don't have to infer the architecture [75].

The graph only helps if the agent calls it. In CodeCompass, runs that used the tool reached 99.5% coverage, and runs that skipped it reached 80.2% [11]. My read: push context through hooks or skills rather than relying on the prompt.

6.2 Toil reduction campaigns

Software Engineering at Google defines a large-scale change as a set of logically related changes that can't be submitted as one atomic unit [92]. Campaigns automate that kind of work, and a code graph tells you where the work is.

  1. Work out the impact set first. Google's migration tooling follows Kythe references up to five hops out from a field, then has an LLM fill the accuracy gaps [57]. Over 39 migrations, the LLM generated 74.45% of the code changes, and developers estimated a 50% time saving [57].
  2. Run deterministic upgrades. OpenRewrite recipes transform LSTs, and Moderne runs them across thousands of repos [65].
  3. Open, track and merge PRs across the fleet. Batch Changes tracks every changeset until it merges [64]. At Spotify, Fleetshift picks targets, schedules work and tracks progress while the Honk agent edits the code, and Fleet Management has merged more than 2.5 million automated PRs [93].
  4. Delete dead code and stale flags. Uber's Piranha has removed around two thousand stale feature flags along with their code [94]. Meta uses Glean to find unused C++ includes and automate the cleanup [59].
  5. See what's blocked. Moderne Changelog shows agents what's ready, blocked or waiting, over MCP [3]. Meta tracks API migration progress with Glean [59].
  6. Give LLM migrations rich context. Airbnb's prompts included sibling tests, imports and the component source [95]. It moved nearly 3.5K test files in 6 weeks [95], against a manual estimate of 1.5 years [96].

For scale: about half of Spotify's pull requests have been automated since mid-2024 [97].

6.3 Automated code review

  1. Show the blast radius, not just the diff. Greptile queries its graph for the dependencies and usages of a changed function [63]. code-review-graph lists the callers, dependents and tests a change can reach, with a risk score [46].
  2. Pull cross-file definitions into the review. CodeRabbit maps definitions and references and finds files that tend to change together [38].
  3. Ground GitLab MR review in the SDLC graph. Compare the Market's Orbit-grounded reviewer matched about 70% of expected inline comments. RAG matched about 58%, worse than adding no context at all [2].
  4. Mix deterministic findings into AI review. Copilot code review combines LLM analysis with CodeQL and ESLint [82].
  5. Pick the tests a change can reach. A hackathon team used Orbit's whole-codebase call graph for this [24], and Meta uses Glean for test selection [59].
  6. Cut noise with reachability. Harness uses Qwiet's reachability analysis to cut noise and focus on real risk [43].
  7. Index diffs for review tooling. Meta turns diffs into "diff sketches" that drive lint rules and notifications [59].

One caution on the headline number. Compare the Market measured alignment with a golden set, scored by an LLM judge, on 79 MRs, and the authors call the result directional [12].

6.4 Knowledge graphs

  1. SDLC context graph. Orbit links merge requests, pipelines and vulnerabilities to projects and code [13], and engineers use it to trace changes and investigate incidents [98].
  2. Incident forensics. A financial services company traced a build-system outage to a CI job that failed 50% of the time [2].
  3. Code, docs and infrastructure in one graph. codebase-memory-mcp links docs, architecture decisions and Terraform or Kubernetes config to the code [8].
  4. Architecture as data. Prethink emits FINOS CALM diagrams and an optional knowledge graph [76].
  5. Decisions and team knowledge. Potpie indexes decisions, source history, team knowledge and workflows [48].
  6. Facts that change over time. Graphiti gives every fact a validity window and traces it back to the source episodes [20].
  7. An org-wide fact store for code. Meta's Glean serves code navigation, search, docs and RAG for AI coding assistants [59].
  8. Mixed corpora. Graphify merges code, PDFs and images, and tags each edge as extracted, inferred or ambiguous [44].

7. How much to trust the numbers

Most of them come from vendors. Orbit, CodeGraph, Augment and codebase-memory-mcp all publish their own benchmarks [2, 7, 8, 40]. I found one public customer A/B test: Compare the Market ran baseline, Orbit, RAG and Orbit plus RAG on 79 real MRs [12].

Corpus size matters as well. Graphify's token reduction was about 1x on a 6-file corpus and 71.5x on 52 files [44].

My read: star counts measure attention, not production use. Graphify passed 149k stars within about seven and a half months of its creation in April 2026 [44], so treat stars as a weak signal.

8. How I'd decide (my read)

Score each option on these questions:

Criterion What to ask
Precision Compiler-grade (SCIP, LST, CodeQL) or tree-sitter heuristics?
Scope Code only, or code plus MRs, pipelines and deployments?
Freshness Updates on every commit or file save, or scheduled re-indexing?
Access control Are results permission-aware across repos?
Agent ergonomics How many tools, and how long are their descriptions? Some clients truncate long ones [72].
Deployment and license When can we self-host, and on what commercial terms?
Cost per query Graph calls add latency and spend [12].

Then work through these in order:

  1. Build the eval harness first. Reuse Compare the Market's four-arm design (no context, graph, RAG, both) on real MRs [12].
  2. Pick the base layer. If the code lives on GitLab, trial Orbit Remote. If it spans hosts, trial Sourcegraph. Keep codebase-memory-mcp or CodeGraph as a local, MIT-licensed baseline.
  3. Pick the campaign layer. Pilot Moderne on one JVM migration and count merged PRs and blocked changes.
  4. Check licenses early. GitNexus is noncommercial [45]. CodeQL's CLI terms restrict private code [31]. Orbit uses the GitLab EE license [23].
  5. Confirm self-hosting dates. Orbit Self-Managed and Dedicated come after GA [2], and Sourcegraph Self Hosted is on request [22].

Next actions

  • Ask GitLab for the Orbit Self-Managed date and its RBAC model.
  • Run the four-arm MR review eval on 50 to 100 internal MRs.
  • Pick one campaign, such as a Java or Spring upgrade, for a Moderne pilot.
  • Index two or three large repos locally with codebase-memory-mcp and CodeGraph as a free baseline.
